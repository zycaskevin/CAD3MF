# CAD3MF v0.1 Strategy Amendment

**Date:** 2026-09-05  
**Status:** Active implementation direction

## Decision

CAD3MF continues development, but it is not positioned as a replacement for Blender or as a proprietary text-to-3D foundation model. Its primary v0.1 path is:

```text
User intent
  -> ChatGPT / Agent host
  -> CAD3MF MCP
  -> revisioned CAD-IR
  -> deterministic geometry build
  -> validation
  -> STEP / STL / 3MF + interactive preview
  -> physical manufacturing
```

For ordinary parametric engineering parts, the preferred experience is direct ChatGPT -> CAD3MF. Computer-use workflows that drive Blender or another graphical CAD application are reserved for geometry that CAD3MF does not yet represent well, especially free-form or artistic modeling.

## Product boundary

CAD3MF owns:

- the revisioned design contract
- deterministic parameter changes
- validation of the resulting geometry
- immutable engineering artifacts
- controlled preview/export delivery
- later manufacturing and measurement receipts

CAD3MF does not need to own:

- a general-purpose CAD GUI
- artistic sculpting
- a proprietary text-to-mesh model
- computer-use automation of Blender

## v0.1 completion gate

The direct ChatGPT path is live and has passed software-side acceptance. A minimal physical print receipt schema is also implemented. The final v0.1 release gate is now the real print of a canonical revision followed by measurement of critical dimensions and fit.

## Post-v0.1 priorities

1. Persist and expose physical print receipts through the runtime only after the first real receipt proves the workflow.
2. Add printer/material tolerance profiles only after collecting physical evidence.
3. Keep provider/backend expansion behind the CAD-IR/compiler boundary rather than bypassing revision and validation semantics.
4. Use external AI/CAD providers only where they materially expand geometry coverage.
